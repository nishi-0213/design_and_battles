# 設計＆戦闘ゲーム 設計書

## 目的

機体などを設計し、戦闘するゲームを開発する。
具体的なゲームルール、設計対象、戦闘方式は今後の会話で決める。

## 技術構成

- 描画: PixiJS 8
- 言語: JavaScript（将来 TypeScript の採用も検討可能）
- シェーダー: GLSL
- 描画効果: pixi-filters
- 描画バックエンド: WebGL

## 現在の実装

`Main.js` をエントリーポイントとして用意した。

- `main()` で PixiJS の Application を初期化する。
- 画面サイズに合わせて描画領域を変更する。
- 中央に HULL SIZE モニターを配置する。
- pixi-filters の GlowFilter でモニターの見出しに発光効果を付ける。
- 戻り値の `destroy()` で描画リソースを破棄する。

以前の描画確認用の仮の機体は取り外した。
独自 GLSL シェーダーは未追加。

## 機体の設計

### 確定事項

- PNG のドット絵風ブロックを重ねて機体を構成する。
- 画面中央の「HULL SIZE」モニター内に機体と操作ボタンを表示する。

### 現在の表示の土台

- `HullMonitor.js` にモニターを実装した。
- モニター上部に見出し、中央に機体表示エリア、下部にボタン配置エリアを用意した。
- 機体用 `shipLayer` とボタン用 `controlsLayer` を分けている。
- 機体表示エリア外の描画はマスクで隠す。
- モニターは画面中央に配置し、小さな画面では縮小する。
- 800 × 560 のモニター寸法と 24 間隔の補助線は暫定的な表示設定であり、ゲーム内の HULL SIZE やブロック寸法ではない。

### 未決事項

- PNG 素材、ブロック寸法、重なり順、配置操作、接続ルール。
- HULL SIZE の意味・単位・制限と、必要なボタンの種類。
- 素材読み込みと配置操作は未実装。現段階の機体・ボタン用レイヤーは空。

### 検証

- 本番ビルド成功。
- Chromium のソフトウェア WebGL でモニター表示を確認。1100 × 800 画面で中心座標が (550, 400) になることを確認。
- 390 × 700 への画面リサイズを確認。JavaScript 実行エラーなし。

## 起動と公開

- Vite を開発サーバーとビルドに使用する。
- `index.html` → `bootstrap.js` → `Main.js` の順に起動する。
- Node.js 24 を推奨する。`npm ci` で依存関係を導入し、`npm run dev` で起動する。
- `npm run build` で `dist/` に静的ファイルを生成する。
- GitHub Pages 用の Actions を用意する。公開にはリポジトリの Pages の Source を GitHub Actions に設定する必要がある。
- インストール、本番ビルド、Chromium（ソフトウェア WebGL）での機体描画と画面リサイズを確認済み。
- GitHub Pages への公開と公開先での動作は未確認。
